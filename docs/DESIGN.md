# EMBERDEEP — Internal Development Specification

Revision 1.1 · Android · Kotlin · zero runtime dependencies

This is the studio document the build follows: what the game is, how every
system behaves, what the technical budget is and how the result is verified.
It describes the shipped implementation, not an aspiration.

---

## 1. Vision

**One line:** a Dungeons & Dragons-style turn-based roguelike dungeon crawler,
designed for one thumb, that fits in a 1.5 MB APK and runs at 60 fps on a
mid-range phone.

**Design pillars**

1. **Real d20 rules.** `d20 + attack bonus vs AC`, dice-based damage,
   natural 20 crits, natural 1 fumbles. Players who know tabletop RPGs should
   recognise every roll.
2. **A run is a story with an ending.** Ten floors, permanent death, a banked
   treasury, and a dragon at the bottom that you either kill or die to.
3. **Thumb-sized tactics.** Every decision is a tap. No keyboard, no virtual
   d-pad, no precision dragging, no reaction-time skill checks.
4. **Cheap to run, cheap to ship.** No asset pipeline, no network, no ads, no
   telemetry, no third-party SDKs. Everything on screen and in the
   headphones is generated by code.

**Player experience target:** ten to twenty minutes per run; tense but fair;
"one more try" after death; visible progress even in defeat (gold banked, best
floor recorded, new classes unlocking).

---

## 2. Technology decision

| Option | Why not |
|---|---|
| Unity / Godot | 20–60 MB of runtime and an engine-specific asset/build pipeline for a 2D tile game that draws maybe 60 sprites a frame. |
| LibGDX | Closer, but adds a dependency tree (gdx, natives, freetype) and a second architecture (its own ApplicationListener) on top of Android's lifecycle. |
| Jetpack Compose | Excellent for menus; wrong tool for a tile renderer with fog of war, particles and a 60 fps loop. Adds Compose runtime + AndroidX. |
| **Custom `SurfaceView` canvas engine (chosen)** | ~1.4 MB APK, no runtime dependencies to break or maintain, full control of the frame budget, and the turn-based rules engine sits in pure Kotlin that can be unit-tested and simulated headlessly. |

**Stack**

- Kotlin 1.9.24, JVM target 17, Gradle 8.x + AGP 8.5.2, R8 + resource shrinking.
- `minSdk 24` (Android 7.0) · `targetSdk`/`compileSdk` 34 · `applicationId`
  `com.emberdeep.game` · portrait only · offline only · `VIBRATE` is the only
  permission.
- Runtime dependencies: **none** (Kotlin stdlib only). Test-only dependencies:
  JUnit 4 and a JVM build of `org.json`.

## 3. Core gameplay loop

```
        ┌────────────────────────────────────────────────┐
        │  MENU → pick class → descend into floor 1       │
        └───────────────────────┬────────────────────────┘
                                ▼
   ┌───────────────────────────────────────────────────────────┐
   │  FLOOR LOOP (turns)                                       │
   │   tap to move / attack / wait / use item / ability        │
   │            ▼                                              │
   │   turn engine resolves the action, then every monster acts│
   │            ▼                                              │
   │   loot, XP, level-ups, doors, hazards                     │
   │            ▼                                              │
   │   find the stairs → descend (autosave)                    │
   └───────────────────────┬───────────────────────────────────┘
                           ▼
                floor 10: defeat the Ember Dragon
                           │
             victory ──────┴────── death
                │                    │
        gold + 300 banked      half of gold banked
                └────────┬───────────┘
                         ▼
          MENU (treasury, best floor, class unlocks) → next run
```

A turn consumes: player status ticks, ability cooldown, monster turns (each
monster: status, then wake/act), FOV recomputation, and an autosave every ten
turns.

## 4. Controls (mobile-first)

| Input | Action |
|---|---|
| Tap a visible floor tile | Walk there (auto-walks when no awake monster is in sight, single careful step in combat). |
| Tap an adjacent enemy | Melee attack. |
| Tap a distant enemy | Auto-walk toward it, stopping adjacent. |
| Tap your own tile | Wait one turn. |
| Ability button (bottom left) | Fighter: Whirlwind · Rogue: Shadowstep (then tap a visible tile) · Mage: Firebolt (then tap a visible enemy). |
| Wait / Bag / Menu buttons | Wait a turn · open the pack · pause. |
| Contextual "Descend the Stairs" | Appears only when standing on the stairs. |
| Android back button | Cancels targeting, otherwise pauses; back again from the menu exits. |

Touch targets are ≥ 46 dp with a 6 px capture pad; buttons dim on cooldown and
show the remaining turns; every accepted input gives haptic + audio feedback.

## 6. Player systems

**Classes** (`ClassType`)

| | HP | Hit die | ATK | AC | Damage | Ability | Cooldown | Unlock |
|---|---|---|---|---|---|---|---|---|
| Fighter | 32 | +7/lvl | +4 | 14 | 1d8+1 | Whirlwind: strike every adjacent enemy with +4 damage | 5 turns | free |
| Rogue | 22 | +4/lvl | +5 | 13 | 2d4+1 | Shadowstep: teleport to a visible tile, next hit auto-crits | 7 turns | 150 g |
| Mage | 18 | +4/lvl | +4 | 11 | 1d6 | Firebolt: 3d6 fire + 3 turns burning on a visible enemy | 5 turns | 400 g |

**Derived stats**

- `attack bonus = class base + (level-1)/2 + 3 while Might is active`
- `AC = class base + armour bonus + 4 while Stoneskin is active`
- `damage = weapon dice (or class dice) + (level-1)/2`
- XP: `level n → n+1` costs `20 + (n-1) × 25`. Each level adds `hit die + 2`
  max HP and **fully heals** — a deliberate earned reprieve.
- Inventory: 10 slots; potions and scrolls stack.

## 7. Enemy systems

Nine monsters, each with a floor band and a spawn weight.

| Monster | HP | ATK | AC | Damage | XP | Behaviour |
|---|---|---|---|---|---|---|
| Giant Rat | 6 | +2 | 10 | 1d3 | 6 | swarm filler |
| Goblin | 10 | +3 | 12 | 1d4+1 | 10 | melee |
| Skeleton | 14 | +4 | 12 | 1d6+1 | 14 | melee |
| Skeleton Archer | 11 | +4 | 11 | 1d6 | 16 | **ranged** to 5 tiles, needs line of sight |
| Orc Brute | 24 | +5 | 13 | 1d8+2 | 24 | heavy melee |
| Ember Cultist | 16 | +5 | 12 | 1d6+1 | 26 | ranged to 4 tiles, sets the hero burning |
| Deep Wraith | 20 | +6 | 14 | 1d6+2 | 34 | **drains** half the damage dealt as health, phases through walls |
| Cave Troll | 40 | +6 | 13 | 2d6+2 | 48 | **regenerates** 2 HP/turn unless burning |
| **The Ember Dragon** | 150 | +8 | 16 | 2d8+3 | 500 | boss: fire breath (3d6 + burning) every 4th turn within 6 tiles, guarded by cultists |

- Depth scaling: `+1 max HP per floor past its minimum`, `+1 ATK / 3 floors`,
  `+1 damage / 4 floors`, `+3 XP per floor`.
- AI: a monster sleeps until the hero is visible within 7 tiles (or within 2),
  then chases with A*, attacks when orthogonally adjacent, and shoots when it
  has a ranged attack plus line of sight. Tiles held by other monsters cost
  extra (6 vs 1), so packs take detours instead of jamming a corridor.
- Spawn budget per floor: `4 + 2·floor/3 + rand(0..2)`.

## 8. Combat

Classic d20 resolution (`systems/Combat.kt`):

```
attack:  roll = d20
         natural 20      → hit and crit (double the weapon dice)
         natural 1       → miss
         roll + ATK < AC → miss
damage:  dice(weapon or class) + bonuses, minimum 1, applied immediately
```

Everything is resolved through the seeded `Rng`, so a run is reproducible from
its seed and the same seed replays identically in tests.

## 9. Items and economy

| Category | Items |
|---|---|
| Weapons | Rusty Dagger 1d4+1 · Short Sword 1d6+1 · War Axe 1d8+2 · Flame Brand 1d10+3 · Emberfang 2d6+4 |
| Armour | Leather +1 AC · Chain +2 · Plate +3 · Emberplate +4 |
| Potions | Healing 16 HP · Greater Healing 40 HP · Might (+3 ATK / 25 turns) · Stoneskin (+4 AC / 25 turns) |
| Scrolls | Fireball (4d6 to every visible enemy + burning) · Blinking (teleport at random) |
| Currency | Gold piles; 35 % of kills drop gold; every floor guarantees 1–2 healing potions |

Treasury is the meta-currency: on death the hero banks `gold / 2`, on victory
`gold + 300`. It buys the Rogue (150) and the Mage (400).

## 10. Level generation

- Standard floors: grid `min(34 + 2·floor, 46)²`, `7 + floor/2` rooms placed by
  rejection sampling, each new room connected to the previous one by an
  L-shaped corridor, doors placed where a corridor meets a room wall at ~55 %,
  ember vents scattered on the floor, stairs at the centre of the last room.
- **Connectivity is proven, not assumed:** after generation the map is flood
  filled from the entrance and any orphaned room is joined to the nearest
  reached room (bounded to 8 repairs). Tests assert full reachability of every
  room, monster and treasure pile.
- Floor 10 is a hand-authored arena: an entry chamber, a throat and the dragon's
  hall, with a guard and guaranteed endgame loot.
- Loot tables bias toward the best tier unlocked by the current floor.

## 11. Progression

- **In-run:** levels, gear, consumables, gold, kills.
- **Meta (profile):** treasury, unlocked classes, best floor, victories, runs,
  total kills, settings. All of it survives death, reinstalls of the run, and
  corrupt files.

## 12. UI

Single-canvas HUD in the dungeon palette: HP bar, XP bar, class/level, floor,
gold, status chips (Might / Stoneskin / BURNING / Lethal), boss health bar,
minimap (toggleable), a five-line fading message log, floating combat text,
targeting banner, and chunky bottom action bar. Menus are the same canvas kit
(`Btn`, `Draw`) so there is exactly one UI technology in the app.

---

## 13. Audio and feedback

Fully synthesised at startup on a background thread into a `SoundPool`
(15 effects: hit, crit, miss, hurt, pickup, gold, level-up, stairs, death,
victory, fire, heal, door, teleport, click) plus a generated ambient music loop
on an `AudioTrack`. Music and sound are independently toggleable; audio failure
is caught and the game simply runs silent. Haptics use amplitude-scaled
one-shots on API 26+ with a legacy fallback. Damage produces particles, screen
shake, hit flashes and floating numbers; the screen flashes on floor change.

---

## 14. Save system

- Files in `filesDir`: `run.json`, `profile.json` (+ `.bak` of each).
- Writes are atomic: temp file → rename, with the previous good file rotated to
  `.bak` first, so a kill mid-write cannot destroy the last good save.
- Reads are defensive: a corrupt primary is deleted and the `.bak` is tried; if
  both are unreadable the run is reported as absent, the menu stops offering
  "Continue", and the game starts clean instead of crash-looping.
- Autosave every 10 turns, on descending, on inventory/pause actions and on
  `onPause`. Autosaves are **serialised on the game thread** (a consistent
  snapshot) and **written by a background worker**; `flush()` is called on
  lifecycle boundaries so the newest state is on disk before the process can
  be killed.
- Format: JSON, `SAVE_VERSION` field, map tiles/variants/explored bitmaps
  Base64-packed, RNG state stored so the exact sequence resumes.

## 15. Settings

Sound, music, haptics and minimap toggles, plus "Erase all progress" with a
confirmation. Settings live in the profile and are saved immediately.

## 16. Android configuration and lifecycle

- Portrait-locked, immersive sticky fullscreen, screen kept awake, no
  action bar (`Theme.Material.NoActionBar.Fullscreen`).
- `configChanges` handles rotation/size changes without recreating the
  activity; the renderer rescales and drops its sprite cache on resize.
- `onPause` → pause audio, save the run and profile, flush the writer thread.
- `onResume` → re-apply immersive mode, resume audio.
- `onDestroy` → close the save worker, release audio.
- Back button: cancels targeting → closes overlays → exits.
- Safe areas: the HUD insets itself from the screen edges; no content sits in
  the gesture/navigation strip.
- Aspect ratios: layout is derived from the actual surface size with a UI scale
  (1.0 ≈ a 392 × 700 dp phone), so tall, square and tablet screens all work.

## 17. Performance budget

| Target | Practice |
|---|---|
| 60 fps cap, `dt` clamped to 1/15 s | fixed-timestep-independent logic, frame-rate independent movement |
| Zero allocations in the render loop | pooled particles and floating text, cached procedural sprites keyed by a packed `Long`, reused canvas/paints/rects, reused minimap bitmap |
| Sub-millisecond monster turns | flat-array A* on grow-only scratch buffers (no per-search allocation), no `HashMap`/`PriorityQueue` churn |
| No jank while saving | serialise on the game thread, write off-thread, flush only at lifecycle boundaries |
| ~1.4 MB APK | no runtime dependencies, R8 + resource shrinking, no image/audio assets |

## 18. Architecture

```
app/src/main/kotlin/com/emberdeep/game/
├── MainActivity.kt      lifecycle, immersive mode, back handling
├── core/                engine only: game loop, screen stack, UI kit,
│                        procedural sprites, synthesised audio, particles,
│                        codec (Base64), seeded RNG, palette
├── model/               pure data: classes, items, monsters, map, game state
├── gen/                 dungeon generation + loot tables
├── systems/             turn engine, d20 combat, FOV, A* pathfinding, run setup
├── data/                profile + save manager
└── ui/                  menu, class select, game screen/HUD, overlays, results
```

**Dependency rule:** `model`, `gen`, `systems` and `data` never import
`android.*` — they are pure JVM Kotlin, which is what makes the whole game
simulatable in tests. Android types live only in `core` (engine/rendering/
audio) and `ui`.

## 19. Verification

Everything below runs in CI on every push (`./gradlew :app:testDebugUnitTest`):

| Suite | What it proves |
|---|---|
| `CodecTest` | RFC 4648 vectors, round-trip fuzzing over 300 byte lengths, malformed input returns null instead of throwing |
| `RngTest` | seed determinism, save/resume of RNG state, bounds of `nextInt`/`range`/`dice`, calibrated `chance`, statistical behaviour |
| `CombatTest` | minimum damage, damage applied, natural-20 always hits, AC scaling, gear and level both increase damage, monster attacks respect AC |
| `FovTest` | own tile visible, walls hide what is behind them, radius respected, exploration is sticky, line of sight blocked by walls/doors |
| `PathfinderTest` | straight corridors, blockers, detours around monsters, unreachable/invalid targets, explored-only search, determinism, every monster in a generated floor can reach the hero |
| `DungeonGeneratorTest` | on 6 seeds × all 10 floors: full connectivity of every room/monster/treasure tile, spawn bands, depth scaling, exactly one reachable dragon on floor 10, deterministic generation |
| `PlayerTest` | XP curve and multi-level payouts, inventory cap and stacking, derived AC/ATK/damage, class unlocking |
| `SaveManagerTest` | full run round-trip, no temp files left behind, `.bak` recovery from a corrupt primary, corrupt-everything recovery, unknown unlocks dropped, profile defaults, `resetAll`, async autosave reaching disk after `flush()` |
| `SimulationTest` | the real `TurnEngine` playing complete expeditions with a scripted bot: invariants checked after **every turn** (hero on walkable ground, HP bounds, no two monsters on a tile, no dead monster still listed, stairs usable, finite positions, inventory sanity), all runs terminate, the dragon is reachable, the game is winnable, a levelled/geared hero can kill the dragon, and floor one cannot kill a hero before it can act |

Plus a printed balance report (win rate, floor histogram, kills, levels, turns)
published to `ci/last-test-run.md` by the workflow.

Manual QA matrix before a release: first launch, new game per class, tapping
through a full floor, pause/resume, backgrounding mid-fight, killing the app
mid-run and resuming, corrupted `run.json`, corrupted `profile.json`, death,
victory, restart, both overlays, settings persistence, back button from every
screen, rotation attempts, small (4") and large (10") screens, low-memory
recreation.

## 20. Build and release

```bash
./gradlew :app:testDebugUnitTest     # tests + balance simulation
./gradlew :app:assembleDebug         # installable debug APK
./gradlew :app:assembleRelease       # signed, minified APK
./gradlew :app:bundleRelease         # Play Store AAB
```

Release checklist: version code/name bumped, R8 + shrinking on, signing config
supplied (`EMBERDEEP_STORE_PASSWORD` / `EMBERDEEP_KEY_ALIAS` /
`EMBERDEEP_KEY_PASSWORD` override the committed demo keystore), no debug
logging, no placeholder content, README current, `dist/` refreshed by CI.

## 21. Known limitations and next steps

- Balance is tuned against a scripted bot (see the CI balance report), not
  against humans; treat the win rate as an upper bound on a careful player.
- No cloud saves, no leaderboards, no achievements — offline by design.
- Procedural art/audio is a deliberate placeholder system: `Sprites.kt` and
  `Audio.buildSfx` are the only two places to touch when real assets arrive.
- Localisation: UI strings are drawn on canvas; a resource-based string table
  would be needed for translation.
